## 1. 路线判断

本工程不按“先把全部数据和模型建完”的方式推进。原有四个研究阶段保持不变，并在S1和S2之间增加一个实现重整阶段S1R。

每个阶段只解决一个层次的问题，完成后必须停下来验收；没有批准，不进入下一阶段。原有26步仍然保留为详细任务库，但不再作为日常推进界面。

```text

  ↓ G0
S1 日频资金状态最小闭环
  ↓ G1
S1R 通用组件替换和来源适配器重整
  ↓ G1复审

  ↓ G2
```

## 2. 研究阶段与S1R实现阶段

### S0：研究合同和数据边界

目标：先固定问题、口径、数据位置和验收规则，防止边采集边改变结论。

主要工作：

- 冻结H1—H4、禁止推断和可证伪条件；
- 冻结市场范围、日期字段、证券代码、单位和时区；
- 建立数据目录合同和来源/许可登记规则；
- 只登记现有Qlib、资金流冒烟样例和历史报告，不迁移数据；
- 确定第一个闭环的输入、输出和Harness状态语义；
- 建立项目状态、决策和工作包管理方式。

主要输出：

- `README.md`
- `ROADMAP.md`
- `STATUS.md`
- `DECISIONS.md`
- `DATA_CATALOG.md`
- `protocol/` 下的研究、数据、会计和报告合同

阶段门 `G0`：研究口径、数据合同、存储边界和第一个闭环范围得到批准。

本阶段不做：正式抓数、模型训练、分钟数据、Qlib迁移和投资结论。

### S1：日频资金状态最小闭环

目标：先把可以直接观察和进行会计核验的日频数据做正确。

第一批只包括：

- 现有日行情的只读引用；
- ETF份额和NAV；
- 沪深融资融券；
- 统一日频资金状态账本；
- ETF规模变化分解；
- 融资余额恒等式；
- 数据缺失、冲突和过期状态；
- 固定好样本、坏样本和一份示范状态报告。

主要输出：

- 可审计的raw、normalized和manifest；
- ETF与融资日频账本；
- 会计恒等式测试；
- `capital_flow_attribution` Harness目标；
- 只陈述事实、代理和不确定性的示范报告。

阶段门 `G1`：来源、字段、日期、单位、覆盖率和会计恒等式全部通过；坏样本被正确识别。

本阶段仍不回答精确机构/散户金额，也不建设多年分钟数据。

### S1R：通用组件替换和来源适配器重整

目标：在不改变S0/S1研究合同和冻结v10的前提下，拆分单体流水线，并把HTTP重试、列式存储和表结构校验交给成熟组件。

主要工作：

- 使用Tenacity统一重试和退避；
- 使用DuckDB和Parquet建立本地数据目录与查询层；
- 使用Pandera执行字段、状态和唯一键校验；
- 把AKShare和Tushare Pro实现为可选二级适配器；
- 保留官方来源、raw哈希、PIT、会计和未知残差规则；
- 从冻结raw重建同一20日窗口并与v10比较。

主要输出与工作包见 `docs/S1R_ARCHITECTURE.md`。

阶段门仍为 `G1`：S1R只改变实现，不自动消除外部覆盖缺口；必须通过兼容性重建并重新审查G1后才能进入S2。

### S2：资金归因、行业迁移和可切换性

目标：在日频账本可靠后，开始回答资金身份和科技资金去向，但只输出概率、区间和证据强弱。

主要工作：

- 加入基金权益仓位和延迟持仓披露；
- 加入公司增减持、回购、IPO、再融资和解禁；
- 加入订单规模资金流代理和市场广度；
- 按授权情况加入5分钟、近期1分钟数据；
- 建立机构、被动资金、外资、现金散户、融资散户、公司资金和未知资金的部分识别；
- 建立科技行业流向其他行业、ETF、防御资产、现金/退出和未知节点的迁移图；
- 计算1日、5日、20日可切换份额和冲击成本上下界。

主要输出：

- 机构权益敞口区间；
- 散户行为代理账本；
- 行业资金迁移图；
- 资金身份部分识别结果；
- 可切换性和流动性压力报告。

阶段门 `G2`：算法在固定反例、缺失数据、来源冲突和极端流动性夹具上表现符合预期。

### S3：历史验证、持续报告和多因子接口

目标：判断前述模型是否具有跨时期稳定性，并把通过验证的结果转为可持续运行能力。

主要工作：

- 历史市场状态和变点识别；
- 2015、2016、2018、2020、2022、2024、2025和2026案例比较；
- 滚动时间切分、gap/purge、Bootstrap、多重检验和压力测试；
- 协议冻结后的真正样本外验证；
- 散户行为预测机；
- T+1校准和历史修订记录；
- 日常监控、专题研究和项目生命周期管理；
- 冻结合格资金行为特征，提供给多因子工程只读使用。

阶段门：

- `G3`：滚动伪样本外、真正样本外和压力测试通过；
- `G4`：日常报告、T+1校准、失败恢复和多因子读取合同通过。

未经G3，不向多因子发布正式资金因子；未经G4，不宣称系统可以持续运行。

## 4. 文件如何管理

### 4.1 项目控制文件

| 文件 | 作用 | 更新规则 |
|---|---|---|
| `README.md` | 项目定位、入口和边界 | 接口或范围变化时更新 |
| `ROADMAP.md` | 大路线、阶段门和推进顺序 | 只在路线决策变化时更新 |
| `STATUS.md` | DONE、REVIEW、BLOCKED和下一步 | 每个工作包结束时更新 |
| `DECISIONS.md` | 用户批准的数据源、算法和口径 | 只追加已批准决策，不静默改写 |
| `DATA_CATALOG.md` | 数据集ID和可读目录 | 新增或冻结数据集时更新 |
| `protocol/` | 研究、会计、时间点、验证和报告合同 | G0后版本化，修改需新决策 |
| `configs/` | 冻结运行参数 | 每次正式运行保存配置版本 |
| `src/` | 采集、标准化、账本、模型和报告代码 | 按工作包单一写入负责人 |
| `tests/` | 合同、好样本、坏样本和集成测试 | 与功能同步增加 |
| `docs/` | 架构、来源、许可和运维说明 | 不代替协议和状态文件 |

### 4.2 数据文件规则

- `raw` 只追加，不覆盖；保存来源、抓取时间和哈希。
- `normalized` 使用数据族、频率、交易所、年份和必要时月份分区。
- `snapshots` 一旦冻结不得静默修改；修改必须产生新版本。
- `derived` 必须记录完整上游版本和配置，能够重算。
- `manifests` 记录行数、标的数、日期范围、哈希、缺失、冲突和许可状态。
- 大表使用Parquet；小型交换表使用CSV；清单使用JSON；协议使用Markdown。
- 不生成大量单证券小文件。
- 项目代码目录不保存Token、Cookie、账户、券商凭据或商业数据密钥。

### 4.3 工作包和变更规则

每次实施都必须有独立 `task_id`，列明：

- 输入和依赖；
- 只读范围和可写范围；
- 禁止操作；
- 必须产物；
- 验收标准和验证命令；
- 预期状态、实际状态和剩余风险；
- 下游接口。

同一个文件在同一时间只能有一个写入负责人。阶段门前必须提交文件清单、验证结果和REVIEW项。

当前 `${QUANTIFICATION_ROOT}` Git仓库尚无提交，正式实施前是否建立受控基线需要单独决定；本路线图不把现有整个工作区自动纳入版本控制。

## 5. 如何与其他项目共享数据

共享的核心不是复制文件，而是“唯一物理数据 + 统一目录 + 不可变版本”。

### 5.1 共享流程

```text
数据源
  → data/raw
  → data/normalized
  → DATA_CATALOG + manifest
  → 本工程计算
  → data/derived/capital-flow-attribution/<feature_set>/<version>
  → 其他项目按dataset_id和version只读
```

任何项目读取数据时都必须指定：

- `dataset_id`；
- `dataset_version`；
- `schema_version`；
- `available_at`规则；
- `content_hash`或manifest；
- 质量和许可状态。

### 5.2 与多因子的关系

- 现有Qlib快照继续保留在：
  `${QUANTIFICATION_ROOT}\多因子\data\market\snapshots\2026-07-14`。
- S0/S1只在数据目录中登记这一旧位置，不移动、不复制、不建立目录联接。
- 本工程可以只读复用其日行情，但要保留 `RESEARCH_ONLY` 和数据限制。
- 多因子工程不直接读取本工程的raw、临时结果或未验证模型输出。
- 只有通过G3并冻结的资金行为特征，才写入共享 `data/derived`，供多因子按版本只读。
- 多因子现有冻结协议和研究状态不得被本工程改写。

### 5.3 与资金监控技能的关系

- 现有 `a-share-capital-flow-monitor` 暂时保持V0日频监控器定位。
- 技能目录不保存正式历史数据，不承载复杂归因算法。
- 等本工程CLI稳定后，技能只作为薄入口调用稳定命令和生成日常报告。
- 历史 `资金流向skill` 输出只登记为报告产物，不转成项目根或正式数据集。

### 5.4 与Harness的关系

- 本工程未来注册为现有Harness中的 `capital_flow_attribution` 目标。
- Harness读取固定夹具和隔离运行目录，不直接修改正式数据。
- Harness验证字段、会计、时间穿越、缺失、冲突、过度归因和输出路径安全。
- 研究状态与测试状态必须分开：坏样本触发REVIEW，但测试本身可以PASS。
