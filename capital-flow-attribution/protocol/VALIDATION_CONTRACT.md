# 验证合同

协议版本：`0.1.0`  
状态：`FROZEN_FOR_G0_REVIEW`  
冻结日期：`2026-07-18`

## 1. 状态分离

验证必须同时记录：

- 测试状态：`PASS / FAIL / ERROR / SKIP`；
- 数据状态：`OK / MISSING / STALE / CONFLICT / UNLICENSED`；
- 工作流状态：`DONE / REVIEW / BLOCKED`；
- 研究证据：`OBSERVED / PROXY / PARTIALLY_IDENTIFIED / NOT_IDENTIFIED`。

例如，一个坏样本正确触发 `CONFLICT` 时，测试为 `PASS`，数据为 `CONFLICT`，工作流为 `REVIEW`。禁止只显示一个“成功”掩盖研究不可用。

## 2. G0验收

WP-S0-01通过G0前必须满足：

1. 控制文件和七份协议存在且可读；
2. H1—H4、市场范围、证据层级和禁止推断明确；
3. 个股、ETF、融资和互联互通的数据合同明确；
4. ETF、融资、防重复记账和未知资金规则明确；
5. S1的5日探针、20日试点、10GB预算和输出范围明确；
6. 正式来源和误差阈值被显式延后至S1探针决策，不以空白或隐含默认代替；
7. `ROADMAP.md` 未修改；
8. 没有写入数据、报告、技能、Harness、多因子或Qlib目录；
9. 没有进行Git暂存、提交或分支操作；
10. 文件之间不存在冲突的市场、时间或状态定义。

G0通过只允许开始S1来源探针，不代表任何数据源、模型或归因结论已经验证。

## 3. S1字段验证

- 数据集身份、版本、来源和许可非空；
- 证券代码、交易所和证券类型合法；
- `trade_date / published_at / available_at / ingested_at` 关系合法；
- 币种、单位、复权和NAV语义明确；
- 历史证券、行业和互联互通资格按有效期连接；
- 行数、标的数、日期范围和哈希与manifest一致；
- 禁止用零替代缺失。

## 4. S1会计验证

- `AUM = Shares × NAV` 在批准精度内闭合；
- ETF规模变化分解可以重算；
- 融资余额恒等式在批准精度内闭合；
- 融券单位和融资单位不混用；
- 互联互通持股市值拆分数量、价格和汇率变化；
- ETF与底层股票不重复计入；
- 未知残差保留，不强制归因。

## 5. 时间点验证

- 报告输入满足 `available_at <= as_of`；
- 晚到修订不会进入首版；
- 退市、行业和互联互通资格不使用未来状态；
- 港股和内地休市日不前向伪装为新观察；
- 汇率版本在截止点前可用；
- 当前名称不会覆盖历史身份。

## 6. 固定夹具

S1至少建立：

### 6.1 好样本

- ETF份额/NAV精确或在批准精度内闭合；
- 融资余额恒等式闭合；
- 沪深北与香港交易日正常对齐；
- 互联互通资格在整个窗口稳定；
- 报告只使用允许的证据语言。

### 6.2 坏样本

- ETF缺少份额或NAV；
- ETF发生拆分或分红但未调整；
- 融资余额单位错误或日期错位；
- 来源冲突；
- 数据过期；
- 许可不明；
- 晚于截止点发布；
- 资格在窗口内变更；
- 港股休市而内地开市；
- ETF和底层股票重复计入；
- 报告将代理写成机构/散户事实；
- 未知资金被强行分配。

## 7. 报告验证

每份报告至少检查：

- 报告日期、`as_of`、版本和市场范围；
- 来源、许可、覆盖、缺失和冲突；
- 事实、代理、部分识别和无法识别标签；
- 数据修订和样本规模；
- 无保证收益、确定因果或身份过度归因；
- 明确“不构成投资建议”。

## 8. 当前允许的显式延后

以下项目允许在G0时保持“待S1决策”，但必须以有责任人的显式延后项存在，不能只留无责任人的占位文字：

- 每个正式数据族的最终来源；
- 来源许可复核结果；
- 基于披露精度的会计容差；
- S1固定5日和20日起止日期；
- Harness目标的实现和注册。
