# 时间点合同

协议版本：`0.1.0`  
状态：`FROZEN_FOR_G0_REVIEW`  
冻结日期：`2026-07-18`

## 1. 目的

本合同防止未来数据穿越、跨市场日期错位和历史修订覆盖。任何研究结果必须能够重建“在当时截止时间实际可见的数据”。

## 2. 标准截止点

交易日T的首个日频闭环截止点为：

```text
as_of = T之后的下一内地交易日（T+1）09:00 Asia/Shanghai
```

内地交易日历是首个日频闭环的运行锚；周末和内地休市日不产生新的标准截止点。香港市场在该 `as_of` 下使用当时最新且符合各自交易日历的数据，并显式列出市场日期。后续若需要“收盘后版”或“修订版”，必须定义不同的 `report_vintage`。

数据进入某个版本的必要条件：

```text
available_at <= as_of
```

`ingested_at` 晚于 `as_of` 的历史补录数据不能伪装成当时已见数据；它只能进入后续修订版或明确标记的回溯研究集。

## 3. 时间字段

| 字段 | 定义 | 禁止替代 |
|---|---|---|
| `trade_date` | 记录所属交易所的业务日期 | 文件名日期 |
| `effective_at` | 资格、分类、成分或规则开始生效时间 | 当前最新状态 |
| `published_at` | 来源首次发布记录的时间 | 本地抓取时间 |
| `available_at` | 流程最早可合法稳定使用的时间 | 交易日收盘时间猜测 |
| `ingested_at` | 本工程实际取得时间 | 发布时间 |
| `as_of` | 报告允许使用数据的截止点 | 运行完成时间 |
| `revised_at` | 来源修订记录的时间 | 覆盖原始版本 |

来源未提供精确发布时间时，必须使用保守可复现规则，并在manifest记录规则和证据。来源探针后通过新决策冻结具体规则。

## 4. 历史证券与资格范围

- 股票、ETF、行业、指数成分和互联互通资格均按 `effective_at`/`end_at` 连接；
- 退市证券不得从历史样本删除；
- 当日新增或移出互联互通名单必须以实际生效时点为准；
- 不能使用当前港股通名单构造历史港股通股票池；
- 名称和代码变化要保留原始身份映射。

## 5. 跨市场日历

上交所、深交所、北交所和香港交易所分别保存交易日历。任一市场休市时：

- 不得把前一交易日数值伪装成当日新观察；
- 使用 `MISSING` 或“市场休市”原因码区分缺失；
- 跨市场汇总必须标记共同可比较的最近交易日；
- 港币换算使用在 `as_of` 前可得的汇率版本。

## 6. 修订与版本

原始响应只追加。来源修订后：

1. 保留旧原始响应和旧manifest；
2. 记录 `revised_at` 和修订原因；
3. 生成新的 `dataset_version` 和snapshot；
4. 已发布报告不静默覆盖，生成新的 `report_vintage`；
5. 比较首次发布值与最新修订值。

“最新值研究”和“当时可见值研究”必须使用不同数据集版本。

## 7. S1必须测试的反例

- 某字段交易日为T，但发布时间晚于T+1 09:00；
- 港股休市而内地开市；
- 互联互通资格在样本中途生效或失效；
- 同一交易日来源发布两个修订值；
- 抓取时间早于声称的发布时间；
- 当前证券名称或行业被错误用于历史日期；
- 非标准运行日错误扩大了数据资格窗口。

任何反例未被识别，时间点验证为 `FAIL`，研究状态为 `REVIEW`。

## 8. 变更规则

日报截止点、运行日历、保守发布时间推定规则或修订策略发生变化时，必须新增决策并提升协议版本。不同截止点产生的结果不得直接拼接为同一时间序列。
